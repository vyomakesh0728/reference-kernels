# m32 singlelaunch bpreshuffle nodup apack implementation plan

> For Hermes: use subagent-driven-development if executing this plan task-by-task.

Goal: Replace the public exact m32 k512 path with a shape-scoped architectural branch that deletes the standalone A-pack launch law and uses the live B-side contract more directly, with the sole objective of moving the overall mxfp4-mm geomean toward <=7 us.

Architecture:
- Scope only the m32 public exact path first.
- Preserve the live anchor as fallback.
- Treat `b_shuffle` as a first-class operand candidate, but do not force it in if verifying the contract reveals a mismatch.
- The branch is only valid if it does not silently collapse back into per-CTA fused-A duplication.

Tech stack:
- Python submission wrapper in `fp8-mm/submission.py`
- HIP C++ exact kernels embedded in `HIP_SRC`
- MI355X / gfx950 scaled MFMA path

## Candidate card

shape: exact public m32 family (`m32_n2880_k512`, `m32_n4096_k512`)

regime_tag: `m32_singlelaunch_bpreshuffle_nodup_apack_k512`

deleted_cost_center:
- generic `mxfp4_pack_a_fixed` helper launch on the exact public m32 k512 path, including the `a_packed/a_scale` temp law used only to bridge into `mxfp4_mm_kernel_mfma_scale_exact_m32_rawb_k512_unrolled`

expected_upside_band:
- `-3.5 to -5.5 us` on `m32_n2880_k512`
- `-3.5 to -5.5 us` on `m32_n4096_k512`
- about `-1.4 to -2.2 us` overall geomean if both visible m32 cases land

why_larger_than_noise:
- m32 is scored twice in the 6-entry benchmark portfolio
- current benchmark wall is `9.98 / 10.10 us` while fresh profile self is only `2.438 / 2.078 us`
- fresh profile shows `a_pack_share = 0.804 / 0.769` and kernel self only `0.479 us` in both visible m32 cases
- the live public exact m32 path still pays Python workspace allocation + standalone `launch_mxfp4_pack_a_fixed_raw(...)` + exact kernel launch, so the surviving common bucket is whole-call A-pack orchestration rather than MFMA math

exact_symbols_touched:
- `custom_kernel` exact public m32 dispatch (`fp8-mm/submission.py:3812-3826`)
- `mxfp4_mm_hip_mfma_scale_exact_m32_direct_entry_public_k512_owned_workspace` (`fp8-mm/submission.py:2986-3043`)
- `mxfp4_mm_kernel_mfma_scale_exact_m32_rawb_k512_unrolled` and `mxfp4_mm_hip_mfma_scale_exact_m32_rawb_k512_unrolled_only` (`fp8-mm/submission.py:2404-2507`)
- `_get_b_preshuffled_mfma_fp4` (`fp8-mm/submission.py:3631-3638`) as dormant-contract verification only, not as permission to create a new B temp

profile_evidence:
- benchmark anchor: `.agent-loop/harness_runs/mxfp4_mm/20260402-120426-p0p5-runtime-collapse-owned-scaleflat-r1-benchmark/stages/01_benchmark/parsed_metrics.json`
- fresh winner profile: `.agent-loop/harness_runs/mxfp4_mm/20260402-143032-baseline-recheck-profile-r1-harness/stages/01_profile_rocprof/profile/profile_summary.json`
- stale autogenerated m32 card to override: `.agent-loop/harness_runs/mxfp4_mm/20260402-143032-baseline-recheck-profile-r1-harness/stages/01_profile_rocprof/profile/candidate_cards.json`
- stale-card reason: the autogenerated m32 wording still names B-pack/repack even though the live public exact m32 path now feeds raw `b_q` / `b_scale_sh` directly and the fresh profile shows the helper bucket is overwhelmingly A-pack, not B-pack

reuse_factor:
- anchor economics are one A-pack per call reused across all output-column CTAs; the candidate must preserve one-pack-per-call economics rather than relocating quantization into every output-column CTA

duplication_factor:
- must remain `1x` versus the anchor; if any prototype quantizes A independently inside each output-column CTA, effective duplication becomes `128x` for `n4096` or `90x` for `n2880`, and the card fails immediately

saved_global_bytes_per_block:
- do not bank this as a win until the ownership law is proven; the provisional lower bound is deleting the external `8704 B` A-temp bridge per call (`a_packed + a_scale`) plus the matching reload path, but fewer launches alone is not a valid win claim

why_total_quant_work_drops:
- the branch is only valid if it removes the external helper/temp bridge without reintroducing full A quantization inside each output-column CTA; otherwise total quant work rises and the lane is a disguised fused-A reopen

kill_criteria:
- if runtime `b_shuffle` is not layout-compatible with `_get_b_preshuffled_mfma_fp4(b_q)`, immediately downgrade the lane to `m32_singlelaunch_rawb_nodup_apack_k512`
- if the first prototype needs a new per-call B temp to use `b_shuffle`, kill the bpreshuffle thesis
- if any design re-quantizes A per output-column CTA or per `N32` tile, kill it immediately
- if profiled self rises above roughly `2.7 us`, the single-launch thesis is probably gone
- if benchmarked `m32_n2880` and `m32_n4096` do not each improve by at least about `2 us`, treat the branch as a miss even if aggregate geomean noise looks favorable

vetoes:
- do not touch other exact shapes in the first pass
- do not reopen generic fused-A, serial m32 sweep, or AITER lanes
- do not mix this card with MFMA-family switches or unrelated B-side materialization changes
- do not claim a win from launch-count reduction alone without the ownership-law proof above

success_gate:
- both `m32_n2880_k512` and `m32_n4096_k512` improve clearly from `9.98 / 10.10 us` and land at or below `7.5 us`
- overall benchmark geomean falls from `13.406 us` to `<= 12.2 us`
- no non-m32 scored shape regresses by more than `0.1 us`
- correctness passes test + benchmark
