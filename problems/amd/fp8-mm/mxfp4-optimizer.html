Agent Protocol

Optimize → Benchmark → Repeat

Each iteration is atomic. Never bundle unrelated changes. Commit winners, discard losers, document everything, loop until ≤7 μs.

①
Step 1
Analyze
Read current benchmark result. Rank buckets by estimated savings × shapes affected. Confirm no A-pack or m64 violations before planning.
②
Step 2
Plan
Name the bucket, shapes, and mechanism. Estimate geomean delta conservatively. Write one-paragraph justification before touching any code.
③
Step 3
Implement
Branch from active base file. Make the smallest change that tests the hypothesis. No bundled unrelated changes. One bucket per branch.
④
Step 4
Benchmark
Run full harness. Collect geomean + all per-shape latencies. Verify no invalid output, no timeout. Compare to previous best geomean.
⑤
Step 5
Evaluate
Improves → commit new base. Regresses → discard. Neutral (<0.05 μs) → keep only if no shape regressed. Always record delta table.
⑥
Step 6
Decide
If geomean ≤ 7 μs → DONE, report final version + all shape latencies. Else → return to Step 1 with next highest-value bucket.
⑦
Step 7
Document
Log: version tag, bucket attacked, shapes targeted, geomean before→after, per-shape delta table, what worked/didn't, next planned bucket.

# MXFP4 Kernel Optimization — Autonomous Agent Loop

## Mission
Drive geomean latency from ~23 us to <= 7 us.
Active base: .agent-loop/manual/native_scaled_exact_shape_m4_k512_constbody_v130/submission.py
Benchmark harness: .agent-loop/harness_runs/mxfp4_mm/

Run the optimize -> benchmark -> evaluate loop INDEFINITELY until geomean <= 7 us.
Never stop early. Never focus on a single shape only.

## Shape Portfolio (optimize ALL shapes every iteration)
- m16:       38.6 us  [CRITICAL — fattest unfinished shape]
- m64:       30.1 us  [HIGH — only open with measured profiler reason]
- m256:      27.3 us  [HIGH]
- m4:        17.0 us  [MEDIUM — preserve v130 gains]
- m32 4096:  16.7 us  [MEDIUM]
- m32 2880:  16.7 us  [MEDIUM]

Every branch MUST name: which bucket, which shapes benefit, why geomean improves.
A branch that only improves one shape while regressing another is REJECTED.

## 5 Optimization Buckets (attack all, not one)
B1 Launch:     Delete wrapper launches; target zero gratuitous roundtrips per hot shape
B2 Temp Laws:  Rank temps by bytes x freq; eliminate non-A-pack intermediate buffers
B3 Runtime:    Remove Python prep/routing; compiled direct-entry only on hot paths
B4 Setup:      Constant-body + public-shape for m16 first (treat like m4 in v130), then m256
B5 Data Mvmt:  Preserve raw-B contract; minimize non-MFMA bytes on hot path

## A-Pack Rules — NO implementation changes
REJECT: per-CTA re-quant, fixed small CTA sweep, heavy block-local owner
LEGAL only if ALL 3 proven on paper:
  1. True duplication-law break (not local re-quant)
  2. Legal mechanism preserving most of the original tile grid
  3. Proof that total quant work drops across the full tile grid

## m64 Rule
Do NOT merge m64 changes without a measured profiler or exact-contract reason.
v131 and v132 showed m64 is too fragile for naive merges.

## Loop Protocol
LOOP {
  1. ANALYZE   — read benchmark, rank buckets by (savings x shapes affected)
  2. PLAN      — name bucket + shapes + mechanism; check A-pack + m64 guards
  3. IMPLEMENT — branch from active base, one bucket per branch, smallest change
  4. BENCHMARK — run full harness, collect geomean + all per-shape latencies
  5. EVALUATE  — improve => commit new base; regress => discard; neutral => keep if no regression
  6. DECIDE    — geomean <= 7 us => STOP and report; else => back to step 1
  7. DOCUMENT  — version, bucket, shapes, geomean delta, per-shape delta table, next bucket
}

## First-Iteration Priority Order
P1: m16 constant-body + public-shape setup deletion        (B4) — target 38.6 -> ~30 us
P2: Cross-shape temp audit ranked by bytes x call freq     (B2) — multi-shape gain
P3: Launch wrapper audit per hot exact shape               (B1) — multi-shape gain
P4: m256 direct-entry + setup delete                       (B4) — target 27.3 -> ~22 us
P5: m32 residual Python routing audit                      (B1+B3) — marginal overhead

## Winning Branch Criteria
[X] Names the bucket clearly
[X] Improves >= 2 shapes
[X] Moves geomean >= 0.2 us
[X] Does NOT regress any shape > 0.1 us
[X] Does NOT touch A-pack code
[X] Passes benchmark harness clean (valid output, no timeout)

## Stop Condition
Geomean <= 7.0 us AND all shapes pass correctness validation.

If stuck above 7 us after exhausting B1-B5:
  Enter A-pack paper mode:
  - Derive m16 tile grid duplication law on paper
  - No code changes until a legal mechanism is proven
  - Focus question: can m16 reduce A-pack duplication without
    collapsing thin-shape parallelism?
