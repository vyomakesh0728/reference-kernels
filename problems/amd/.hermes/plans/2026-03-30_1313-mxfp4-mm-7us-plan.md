# Plan: mxfp4_mm to ~7 us geomean

## Goal
- Reach <= ~7.0 us geometric mean on MI355X for mxfp4_mm while preserving correctness and portfolio-wide gains.

## Current context / assumptions
- Latest local harness run: fp8-mm/20260329-125150-v135-benchmark
  - geomean: 22.592 us (benchmark_geom_mean_ns 22592.123…)
  - per-shape means: m4 16.9 us, m16 36.1 us, m32 16.8 us, m32(2880) 16.8 us, m64 29.7 us, m256 26.0 us
  - gap to target: ~3.2x
- Optimizer dashboard: target <=7 us, active base v130, hottest shape m16, A-pack still in “research” stage.
- Principle Q&A: prep dominated; A-pack is the main blocker. Thin shapes (m4/m16) are A-pack dominated; wide shapes split roughly 1/3 A-pack, 1/3 B-scale decode, 1/3 kernel. Architectural/scheduling lanes are premature until prep buckets shrink.
- Recent failures show what not to do: inlining full A-quantization per CTA (v102) multiplies work; persistent CTA with too few CTAs (v107) kills parallelism.

## Proposed approach
- Phase 1: refresh profile on the current best baseline to confirm bucket shares and validate A-pack dominance.
- Phase 2: remove A-pack launches for thin shapes without duplicating quantization per output tile.
  - m16 first, then m4, preserving parallelism and existing raw b_scale_sh contracts.
- Phase 3: collapse A-pack for wide shapes (m32/m64/m256) using the same ownership model.
- Phase 4: delete remaining wide B-scale decode by consuming b_scale_sh directly.
- Phase 5: after prep is mostly gone, open a multiplier lane (constant-body clones, scheduling/tiling, alternate instruction families) based on fresh profile evidence.

## Step-by-step plan
1. Baseline audit
   - Confirm which candidate is considered “best” (v130 vs v135) and lock it as baseline.
   - Recompute geomean and per-shape weights from parsed_metrics.json for a clean before/after.
2. Profile the baseline
   - Run profile_rocprof on MI355X for mxfp4_mm baseline.
   - Capture bucket shares (A-pack, B-scale decode, kernel body) per shape.
3. Thin m16 A-pack annihilation (highest leverage)
   - Design a fused ownership model that packs A once per call or per row-block and reuses it across multiple N tiles within the same launch.
   - Avoid per-CTA or per-tile re-quantization; ensure the CTA count stays close to the baseline (>=100 CTAs for m16).
   - Keep raw b_scale_sh contract and working MFMA body intact.
4. Benchmark/test m16 branch
   - Run test + benchmark; require geomean improvement and no large regressions in other shapes.
   - If m16 improves but others regress, adjust tile grouping or reuse strategy before proceeding.
5. Thin m4 A-pack annihilation
   - Apply the same ownership model with wave64 constraints and small-M specifics.
   - Preserve the known working m4 direct-entry semantics; ensure adequate parallelism.
6. Reprofile after thin wins
   - Confirm kernel_share rises and no prep bucket exceeds ~0.25 on m4/m16.
   - If still prep dominated, iterate on A-pack ownership rather than scheduling.
7. Wide A-pack collapse (m32/m64/m256)
   - Port the A-pack ownership change to the wide path without touching the working MFMA bodies.
   - Keep direct-entry raw b_scale_sh behavior stable.
8. Wide B-scale delete
   - Implement direct-from-shuffled b_scale_sh consumption for wide shapes.
   - Validate correctness against the reference outputs.
9. Multiplier lane (only after prep buckets are small)
   - Explore constant-body clones for fixed K/N shapes.
   - Evaluate scheduling changes (CTA order, wave specialization) once kernel_share >= 0.5.
   - Consider alternate instruction families only with profile-backed justification.

- kernelbot test (correctness) and benchmark (geomean + per-shape)
- profile_rocprof runs for baseline and each major phase
- Guardrails: no single-shape regression >5% unless geomean improves materially; maintain correctness on all test seeds

## Risks, tradeoffs, and open questions
- Risk: A-pack fusion repeating quantization per CTA (v102 failure). Must enforce amortization and CTA count checks.
- Risk: persistent-CTA strategies collapsing grid parallelism (v107 failure). Must maintain near-baseline CTA supply.
- Tradeoff: storing packed A for reuse increases workspace or LDS pressure; need to confirm memory budget.
- Open questions:
  - Best ownership pattern that keeps quantization bounded while preserving parallelism for m16 and m4.
  - Whether wide A-pack collapse should be staged (m32 first) or family-wide.
  - When exactly kernel_share crosses 0.5 to justify architectural lanes.
